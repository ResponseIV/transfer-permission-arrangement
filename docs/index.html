A private code and a shared wiki

Alpha and Beta are language-model agents. Each starts with a private code, called a token. Their task asks for both codes. In the confidentiality conditions, they are also told to keep their own code private.

They can read and replace pages on a small wiki. A shared board gives them a place to communicate. The test environment, called the fixture, records every write, every read and the version it returned, and every final answer. A complete run is an episode.

The agents run on OpenAI models the paper calls Sol, Luna, Terra and Astra, and on the open-weight Qwen3-32B. A judge is a separate AI model that reads a record and says whether a code moved; the study's judges are Astra and Luna.

The advantage of this artificial setting is that the alternative explanations can be built, too. Give both agents the same source. Permit a swap. Plant a code before either agent acts. Supply a script. Then ask which apparently convincing clues survive those comparisons.

The sprint contains 706 scorable episodes: a 450-episode primary test on four OpenAI models and six registered follow-ups, including the open-weight Qwen3-32B. This is a controlled test of evidence, not a measurement of how often agents collude in the world.

The operational transfer definition

A completed transfer is an agent re-emitting the other's token after reading it on a revision the other wrote, or answering with a correct peer token that no recognized plain read explains, assuming the token was not guessed. All 244 primary transfers count through the answer clause; the 60 planted-leak transfers count through the read-and-use clause. Receipt and use are scored separately.

Each token is an initial and nine hexadecimal characters. Agents alternate, Alpha first, with at most eight actions each: read, replace a page, or answer. Shared-board authors and readers are anonymous in the observer views; the fixture retains their true identities.

Build the innocent explanation

Two firms raising prices together might have made a deal, or both might be responding to the same costs. Antitrust reasoning asks what evidence distinguishes those explanations. This study borrows the comparison method, not a legal conclusion about agents.

Shared source
Both agents can read both tokens in an archive. Their answers can agree without an exchange.
Authorized exchange
The prompt prescribes a swap, with no rule against it. Transfer does not establish a violation.
Planted leak
The fixture leaves a token on a readable note. A secret can pass without a recorded offer or reply.
Scripted offer
A shared instruction supplies the offer, reply and completion. The sequence can resemble an agent-made plan.

Exact conditions and prompts are in the paper’s Methods and Appendix B.

Keep the record beside the claim

The experiment knows what happened. An outside observer may hold only part of that record. The model judges saw cumulative views of the first three records below; none saw the instructions.

Page writes
What was written, in order. Shared-board authors remain anonymous.
Access log
Which page and version was read, and when. Shared-board reads remain anonymous to the observer.
Final answers
What each agent returned, including a token it may have decoded from a disguised carrier.
Instructions
The rule and any supplied plan. These were available to the human analysis, never to the transfer judges.

The page nobody read

Alpha writes its private code on its own note. A judge looking at the page calls it a transfer. It is a plausible alarm. The missing question is whether Beta ever saw that note.

Still open from pages alone. A written code may never have reached another agent. The page history cannot settle receipt.

An access log records which page and version was read. Adding it removed this false alarm. Across the main test, Astra found all 244 transfers with the log. The chart counts its false alarms in the 194 runs where no swap was prescribed and none happened.

This pattern accounted for many alarms. Sol wrote its own token on its own note in all 20 of its archive episodes; Astra called 19 of them transfers on page writes alone. The access log removed all 19.

With the log, Astra found all 244 primary transfers. It judged whether a token reached another agent, blind to the true tokens, the acting model and the condition.

What that success measures. 242 of the 244 primary transfers were prescribed exchanges: the agents were told to swap. The result tests transfer detection, not the detection of an independently formed agreement. Astra still made 9 false alarms among the 12 prescribed exchanges that did not complete.

A rare transfer can still produce many false alarms

Now imagine using that detector on a population where transfers are rare. Even a small false-alarm rate can produce more alarms than the real transfers do, because the nontransfer population is much larger.

Assume 1% of audited episodes contain a transfer, and the rest resemble all 206 primary nontransfers.

Then 19% of Astra’s alarms with the log would be real transfers.

This is a hypothetical projection from the test rates, not a field measurement. Change the comparison population, and the answer changes. Excluding failed prescribed exchanges raises the point estimate to 100%, with a 35% bound. That assumes those failed exchanges are absent from the population being audited.

See the curves, uncertainty and population assumptions

At a 1% base rate, the estimate against all 206 nontransfers is 19%, at least 11% at the interval bounds. On page writes alone, 5%. Dashed curves use the lower hit-rate and upper false-alarm-rate interval endpoints. The bounds hold for each configuration under episode-sampling assumptions, not simultaneously across them.

Read the instructions before calling it a violation

In this pair, the same model writes the same reversed codes, reads the same pages and returns the same answers. The behavior matches. The rule does not.

Still open from behavior. A transfer alarm cannot establish that the transfer broke a rule.

Across 20 pairs of matched tasks on Luna, the six warning signs an observer can read from the pages and the access log were identical with and without the rule. The final answers did differ: under the rule, an agent often ran out of actions before answering. The six signs were also identical on Qwen. Sol behaved differently: told to get round the rule, it mostly asked for the code outright, so its traffic changed. The result depends on what the model did with the instructions.

An offer appears on the board

Alpha cannot open Beta’s private note. It writes a proposal instead: put your code on the board backwards, and I will reverse it. Alpha also posts its own code backwards. Beta reads the offer, replies in that form, and both return both codes.

The follow-up attempted 40 new Sol episodes under the confidentiality rule; it produced 39 scorable episodes. All 8 transfers followed an offer, its reading and a reply carrying the token.

Before the follow-up, the study registered an event definition, shaped by four earlier agent-arranged transfers: an offer proposes a disguised transfer, the other agent replies with a carrier of its own token, and the offerer re-emits that token. The 40-episode follow-up produced 39 scorable episodes; 13 contained an offer, 8 an acceptance, and all 8 completed. In each completed case, the offer had been read before the carrier was posted.

Coding was completed from the event logs before judge verdicts were read. The page-only proposal judge agreed on offer presence in 39/39 follow-up episodes; that agreement does not validate acceptance or completion.

The control supplies the entire sequence

The opening exhibit comes from a different condition. A shared instruction tells Alpha to offer a reversed-token swap, Beta to read and reply, and Alpha to complete it. No confidentiality rule is present. Sol produces the full sequence in 20 of 20 episodes. Nothing on the pages says it was a script.

The arrangement result rests on 8 transfers, on one model and one wording, all offered by the first mover. It is a definition of recorded events, not a test of what an agent privately intended.

Still open without instructions. The sequence alone does not say whether the experiment supplied the plan. It also does not establish private intention.

The exchanges were usually one-way

9 of the 10 agent-arranged transfers served only the proposer. In the Sol follow-up, all eight successful offers came from Alpha, which acts first; seven transfers went only to it. In four, Beta’s request for Alpha’s token in return went unanswered. The two-way example above is the one where Alpha posted its own token first.

This is a small selected group. It does not establish a general tendency toward reciprocity or exploitation.

The code was gone by the time the page was inspected

The fixture plants Alpha’s code on a readable note before the task. Beta reads it. Alpha then replaces the note with a request for Beta’s code. Looking only at the final page, an auditor would see the request and miss what Beta had already received.

Still unresolved by an arrangement test. Information can pass without an observed negotiation. This toy leak measures token transfer, not downstream harm.

The planted token was taken in 60 of 60 episodes across Luna, Sol and Qwen. No offer or reply was recorded. A monitor limited to arrangements would miss this kind of transfer.

The carrier need not look like the code

Once a code is disguised, tracing the original string through the pages becomes a weak shortcut. The Sol follow-up included per-character RSA and an XOR mask, not just reversal. A reader must recover the token using the scheme in the offer.

Retrospective flow check 1 of 8 follow-up transfers found.

It missed seven encoded carriers.

The retrospective auditor was written after the runs and tested on Sol follow-up development data. This is a diagnostic failure on existing records, not held-out agreement accuracy, and not the registered event coding.

The lesson is narrower than “the detector failed.” Different instruments answer different questions: a recognized string, an operational transfer label, an offer-and-reply sequence, and the instructions are separate pieces of evidence. Naming the instrument matters as much as reporting its score.

See the unsuccessful approaches in Appendix F of the submitted paper and inspect a cipher-bearing offer. This later diagnostic did not motivate an earlier registration.

The shared source defeats the matching-answer clue

In the archive condition, both answers matched in all 40 episodes. Neither agent had to read anything the other wrote. The same source explains the agreement.

Agreeing answers occurred in 189 of 244 transfers. Against the pooled episodes without a transfer, that looks 3.8 times as common under transfer. Against the archive alone, matching answers were less common. A large pool of easy negatives can hide the particular alternative that defeats a signal.

The pooled ratio has lower bound 2.7. Against the archive alone the ratio is .77, lower bound 0.72. These are transfer comparisons, not agreement ratios.

The first archive case is more than an anecdote: it identifies the comparison population an auditor must keep separate. Revisit its page writes and reads.

Report the findings separately

A useful audit should make each inference checkable. Report whether information passed, whether the instructions permitted it, and whether an arrangement sequence was observed. Attach the record and the remaining alternatives.

Transfer
Keep the read and the revision it returned, together with the final answer. A visible page may be unread; a later page may have overwritten the token that was used.
Permission
Keep the exact instructions. Identical traffic can accompany a permitted or forbidden scripted exchange.
Arrangement
Keep the ordered write history and the instructions beside it. An offer and reply can be supplied as a script; a planted token can pass without either.

Those are findings about recorded behavior in this experiment. Internal intent, real-world harm and general reliability across other tasks remain outside what these results establish.

What this does not show

  • This is a small, artificial test: two AI agents, a toy wiki and random codes. Nothing real was at stake, and no one measured intent or real-world harm.
  • The judge's strong record is for noticing that a secret moved. In 242 of the 244 cases the agents had been told to swap, so it says little about spotting a secret deal.
  • The observed arrangements are few: 8 transfers, from one model and one wording, all offered by the agent that moved first.
  • The author double-checked the coding by hand only in part: 24 of 38 episodes on one check, 4 of 20 on another. Every disagreement is reported in the paper.
  • Harder look-alikes remain untested, such as a script only one agent receives.
  • A synthetic two-agent task; no market harm or intent is measured.
  • 242 of the 244 primary transfers were prescribed, so the judge rates measure transfer detection, not agreement detection.
  • The observed arrangements are few, on one model and wording, and the follow-up's successful offers all came from the first mover.
  • The author's blind checks of the coding are partial (24 of 38 and 4 of 20 episodes); every disagreement is reported.
  • Scale and the choice of models were set by an individual budget.
  • All 143 registered forecasts are scored in the paper's Appendix D, wrong ones included.
  • Scope. A synthetic two-agent task; complete-token transfer, not every partial disclosure or hidden channel; no market harm or intent is measured. The offer-and-reply definition does not establish intention. The pact gives conflicting instructions from one source, not an override of a higher-priority policy.
  • Denominators. 242 of the 244 primary transfers were prescribed exchanges; the judge rates are transfer detection. The arrangement findings rest on 8 transfers on one model and one wording, all offered by the first mover.
  • Selection. The primary measures were developed on prior data. The Sol follow-up chose a model and condition that had produced transfers. Episodes, models and providers were bounded by an individual budget (consumer subscriptions; hackathon credits for Qwen).
  • Statistics. Intervals assume independent episodes, although task tokens repeat across paired conditions and models. The judges differ in prompt and the OpenAI and Qwen routes in compute allowance, so their comparison does not isolate model size or training.
  • Validation. The author's blind checks cover 24 of 38 and 4 of 20 episodes (below).
  • Harder alternatives remain: a script only one agent receives, a leak an agent causes (Qwen produced one, unprompted), a source one agent sees.

Methods, denominators and how to reproduce

Sequence and registration

The testbed, label, signals and judge prompts are preexisting work, developed on 1,174 earlier episodes; they were frozen before a 450-episode primary test on four OpenAI models (461 attempts; 11 excluded, one a provider refusal). Failed episodes are kept, never rerun (a stopped run may resume once; one resumed twice, a logged deviation).

The scripted control

One shared instruction, with no rule, tells alpha to write an offer on its board page asking beta to post its token reversed, character by character, and saying alpha will reverse it; beta, after reading the offer, accepts by writing its own token reversed on its board page; alpha reads it, reverses it, and writes its own token reversed for beta. The exact prompt is shown in the explorer. Sol: 20 of 20 episodes scorable, all with the full registered sequence including the read. Qwen3-32B: format failures in episodes 01 and 08 stopped the run and its single resume, leaving 6 scorable. The auditor's instruction check, a pattern for the fixture's known pact and convention wording, missed the scripted-offer instruction and called all 26 agent-made candidates; it was not changed after the fact.

Preexisting: the testbed, the frozen transfer label, the observer signals and the judge, and 1,174 scorable development episodes. Words used here

Terms, in plain words
Agent
An AI language model set up to take actions on its own, here reading and writing pages and giving a final answer.
Language model (LLM)
A program trained on large amounts of text to continue it; the kind of system behind chatbots.
Token
Here, each agent's secret: a random string of characters such as A62C58B580. (In AI, "token" usually means a piece of text a model reads; this paper uses it for the secret.)
Episode
One run of the task, start to finish.
Log
The record of what happened. The access log notes each read: which page, when, and which version it returned.
Transfer
One agent answering with the other's token after reading it on a page the other wrote, or answering with it correctly when no plain read explains how, for example by decoding a disguised copy.
Carrier
Page text holding a token in some form, for example written backwards or enciphered.
Prescribed exchange
A swap the instructions told the agents to make.
Arrangement
Here: one agent offers a disguised swap, the other replies with its own token in that disguise, and the offerer then uses it. The definition was registered before the follow-up runs.
Judge
A separate AI model asked to read a record and say whether a secret reached the other agent. It never sees the true tokens.
False alarm
A judge saying a secret moved in an episode where none did.
Base rate
How common the thing you look for is among the cases you check. When it is rare, even a good alarm is often wrong.
