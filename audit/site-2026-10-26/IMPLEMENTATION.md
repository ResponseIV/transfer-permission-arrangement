## Editorial result

The article now follows a case notebook: an incriminating-looking private note with a refused read,
matching traffic under different instructions, a recorded arrangement alongside its scripted control,
and a planted token read before its page is overwritten. Each exhibit names the available record,
the supported inference and an alternative left open. Real strings and source links carry the character.

The investigation adds a concrete failure of a retrospective flow check, with its chronology and
development-data limits. The base-rate lesson introduces a hypothetical population before curves and
interval bounds. The research depth has a direct map to definitions, coding, human checks and diagnostics.
The paper entrance is a factual source docket with PDF, text, submitted version and citation links.

The original scientific sources, event data, frozen labels, signals and submitted PDF are unchanged.
`scripts/site_data.py` changes explanatory copy only; generated `episodes.json` reflects those edits.
The final source review restored the explicit count of four earlier agent-arranged transfers that shaped
the registered follow-up definition, now visible at investigation depth as well as research depth.

## Layout

The owner's subsequent review found the type hierarchy and spacing still arbitrary. The presentation
was rebuilt around `docs/assets/tokens.css` and documented in `docs/DESIGN-SYSTEM.md`. Editorial headings use
Newsreader; interface and signposts use Instrument Sans; source strings use JetBrains Mono. The roles
use three weights, 18/28px prose, 14/24px notes/records, 14/20px interface text and a defined heading scale.
There are no component-specific font sizes or shrinking phone source excerpts.

The compact single-line masthead and underlined reading tabs remain. Site navigation is Story / Evidence /
Paper; depth choices are Essentials / Investigation / Research. Spacing uses an 8px unit, shared panel
insets, 48px control targets, 24px phone gutters (16px compact), 48px larger gutters and a 656px prose measure.
Chapter spacing steps through 48/64/80px. The opening record uses its natural height instead of a blank
reserved area. Duplicate responsive overrides and obsolete explorer styles were replaced with a single
composition for each pattern. The desk owns its page-specific CSS and uses the shared roles. No runtime
libraries or visual effects added.

## Verification

- Python website checks cover all reading depths’ numeric claims, source extraction, generated figure
  identity, contrast tokens, links, PDF byte identity and real opening/case excerpts.
- Focused Node checks cover chapter/event restoration, hidden specialist links and disclosure opening,
  plus curated comparison event references and record/fixture boundaries.
- Final automated suite: 31 Python tests and 17 Node tests. Contrast checks read the light/dark palettes
  from the new token source. Every component font declaration uses a named type role; all margin/padding
  and gap values use shared spacing tokens, apart from the 1px screen-reader hiding geometry.
- Chromium renders reviewed at 320, 375, 768, 1024 and 1440px. All eight episodes and three comparisons
  restore explicit record/event/reveal URLs at 375px without horizontal overflow or duplicate IDs.
- Script-free HTML was served locally to exercise the static comparison. A local HTTP 503 for episode
  data verified the error message and retained comparison; a delayed response verified loading context.
  These checks do not claim a browser-level JavaScript-disable setting.
- Actual screen-reader operation, browser print preview, text-only enlargement and browser zoom have
  not been verified. Narrow viewport reflow and programmatic lane names are separate, verified checks.
- Browser click activation passed all 18 depth pairs across Transfer, Arrangement and Limits at 1440px:
  the chapter remained active and its viewport position changed by at most 1px. Pointer/key preparation
  preserves a precise anchor. When activation has already moved the viewport, a still-visible linked
  chapter resolves the preceding-section-tail ambiguity; offscreen route targets are ignored. The separate
  physical keyboard and screen-reader paths have not been exercised, beyond isolated state tests.

No push, publication, repository setting change, scientific run or paid model call was performed.
